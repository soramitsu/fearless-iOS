# Application-authorized transport writes

This candidate extends the exact Fearless 4.0.12 source at `3e1de9baeab87de379e0cb01c64d5db18fbf130f` (`feature/without-origin`). The wallet retains its existing minimum OS. Ordinary read/write APIs remain available. New per-message authorization requires `WSEngine`, `TCPTransport` and no compression; custom/native/foundation transports fail closed for this API.

`write(stringData:authorization:callbackQueue:completion:)` freezes one frame on the existing writer queue, binds it to one connected engine epoch and one `NWConnection`, acquires engine/transport locks, and then invokes the application-owned authorizer. The application must acquire its own authority lock, check its signed intent lease and sample freshness after any durable I/O, and synchronously invoke the handoff at most once. It may not reenter the socket, cancel from inside the authorizer, retain the nonescaping closure, dispatch/await, sign, serialize, or wait for work that depends on the writer. There are no secrets or authorization tokens in this library.

The final operation-state commit uses a nonblocking lock attempt. Contention denies the write; it never waits beyond the application's clock check. Transport then calls `NWConnection.send` synchronously. OS acceptance is the irreversible boundary, not proof that a remote peer received or executed a transaction. The OS may buffer accepted bytes; cancellation cannot recall them.

Cancellation before handoff prevents bytes even when the operation has left the queue and is waiting for authority. Stop first closes the guarded-request registry and cancels pending handles, then invalidates the engine epoch. Cancellation, transport failure, or an authorizer error after handoff reports an unknown outcome. Completion is delivered once and asynchronously outside application/library locks. `cancel()` also returns whether a handoff may have occurred so a request layer can preserve unknown outcomes after reconnect or timeout. A successful transport callback does not establish transaction finality.

Engine and transport locks precede the application authority lock. The short pending-request registry lock is released before cancelling or taking engine locks. Application callbacks never run inside these sections. Stateful compression is not qualified: preparing a frame that is later denied must not advance a shared compressor dictionary. Legacy compressed traffic remains on its original API.

Validation includes 59 tests: 43 authorization/handshake/TCP/generation tests and 16 existing framing/compression regressions. Coverage includes denied authorization, delayed frame/transport work, queued/dequeued cancellation, stop and reconnect, duplicate/missing authorizer action, inline completion reentry, unknown outcomes, legacy writes, unqualified/compressed transport denial, and exact accepted bytes over a real local TCP connection. The iOS framework is compiled at the wallet's existing iOS 15 minimum. These are development checks; independent security review, pinned wallet integration, protected CI and device/distribution acceptance remain required. No production capability is enabled by this change.

The historical header validator allowed a missing `Sec-WebSocket-Accept` and did not require the upgrade/connection fields. It now requires a matching nonce response, `Upgrade: websocket`, and a `Connection` upgrade token, handling HTTP field-name casing and rejecting ambiguous duplicates. This follows [RFC 6455 section 4.1](https://www.rfc-editor.org/rfc/rfc6455#section-4.1). The legacy mock server now produces a real nonce response; its binary framing assertions compare the full payload. The unchanged wallet test baseline must be rerun against this strict handshake before release.

The exact historical base branch is currently unprotected. This candidate does not replace that missing protected-branch/review prerequisite with a local test result.


## Physical connection generations

The follow-up source changes bind every Network state, read, viability, better-path and TLS verification callback to the `NWConnection` generation that created it. Replacing or disconnecting the transport retires that generation. Read continuation always targets its captured connection; obsolete input cannot schedule a receive on a replacement. TLS verification completion is called exactly once even after retirement, with denial for obsolete verification, and cannot report an obsolete failure to the new engine.

Callback admission and engine lifecycle use one outer recursive event lock. The order is event → engine writer semaphore → transport context → application authority; the context lock is released before invoking engine callbacks. The writer does not acquire the event lock. Frame preparation, writer/context waits and connection checks still precede the application authorization sample, followed directly by `NWConnection.send`. Library completion callbacks remain outside the final authority scope. Tests block an event callback while a real authorized write completes to verify that the new event serialization does not add a writer wait after authorization.

Built-in HTTP buffers, the frame collector and the queued frame parser reset when a new engine session begins. Queued decoding captures its original delegate, and session proxies reject obsolete frame/HTTP callbacks. A delayed close completion cannot stop a newer session. The WebSocket callback queue checks the session token immediately before admitting an event; a delegate invocation already admitted before retirement may finish. This is not retroactive withdrawal of callbacks or bytes already accepted by the OS. Custom parser/transport implementations remain responsible for their own lifecycle contracts; the tests qualify the supplied TCP transport and built-in parsers.

Twenty-one additional tests cover stale Network callbacks, exactly-once TLS completion, real local TCP receive/reconnect/write behavior, admission racing replacement, deferred parser and WebSocket queues, incomplete HTTP/frame reset, stale close completion, and stop/reconnect while final authority waits. Physical-device TLS, OS lifecycle testing, independently reviewed immutable source publication and integrated wallet/store qualification remain required.

A stop before WebSocket upgrade immediately retires the transport because it cannot send a close frame. During an established connection, stop marks the engine as stopping. A following start retires that physical connection and starts a fresh handshake instead of returning based on the old `canSend` flag. TCP close frames are uncompressed and carry their captured connection context through the writer queue; the context is checked after frame preparation at the actual TCP handoff. A close queued for a retired connection cannot reach or disconnect its replacement. Ordinary data-write APIs keep their existing behavior. Tests combine stop/start with blocked final authorization and delayed close preparation, and verify the old close context is rejected on a real replacement TCP connection.

Both graceful stop and force-stop close parser and nonterminal event admission immediately, before a close frame can wait in the writer queue. Deferred old HTTP success cannot reactivate `canSend` and suppress the next connection attempt. Current-session terminal error/disconnect/cancel/timeout/waiting notifications remain deliverable until a replacement starts; replacement retires that token completely. Every error uses the same generation-aware broadcast path. Regression tests cover force-stop followed by deferred HTTP/frame callbacks, queued old error delivery across replacement, and terminal error preservation while stopped nonterminal notifications are dropped.
