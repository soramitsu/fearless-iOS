# Guarded JSON-RPC requests

This source candidate builds on the exact compatibility commit `9a91c22b9baa60f7237637a032d4c29159b8e16b` and pins the transport candidate `b6ef58590241babdb4fe52e916a02c9e2b749e3d` from [Starscream PR5](https://github.com/soramitsu/fearless-starscream/pull/5). Both remain candidates awaiting independent review and protected release qualification.

`JSONRPCOptions(writeAuthorization:)` carries an application-owned authorizer to the final Starscream transport handoff. It cannot enable reconnection replay. Ordinary request options retain their existing defaults. `JSONRPCOperation` composes the application guard with operation-owned cancellation state. Cancellation is checked inside the application's fresh-authority scope immediately before handoff, independently of whether the request ID has returned to the operation. That final check never waits for an operation lock. Cancellation and timeout before any handoff attempt return `requestNotSent`; once handoff has been attempted they preserve `submissionOutcomeUnknown` until the application reconciles chain state. The first terminal response is synchronized and retained.

The engine keeps a per-attempt generation alongside the transport cancellation handle. Cancelling an unsent request prevents its queued or dequeued write. Accepted bytes without an RPC result produce `submissionOutcomeUnknown`; neither reconnect nor subscription rescheduling replays guarded mutations. A callback from an old attempt cannot settle a reused UInt16 request ID. Operation cancellation removes a request only when its authorizer identity still matches, so a stale ID cannot cancel another request. Engines without identity-aware removal use a conservative no-op cleanup default; the operation-owned authorizer still prevents a late handoff. A premature server response cannot complete bytes that were never handed off. Guarded request payloads are omitted from pending-request debug output.

Replacing a URL creates a new engine and requires a fresh handshake, cancels guarded work on the old connection, retains ordinary pending reads, and ignores old socket callbacks. Active/retrying connections explicitly reconnect to the replacement endpoint; intentionally dormant connections wait for an explicit connect. State-delegate and RPC response callbacks run outside the RPC mutex, allowing node-failover delegates to replace the endpoint without recursively locking. An already queued retry cannot restart an explicitly disconnected connection. Unsubscription decodes outside that mutex and safely reacquires it only for response bookkeeping, avoiding nested request-lock deadlocks and preserving a replaced subscription.

The application authorizer must hold fresh, intent-bound authority through a synchronous handoff, after its own durable I/O and clock sampling. It must not reenter this SDK, prepare/sign data, wait for writer-dependent work, or retain the nonescaping closure. It contains no secret-key material. The app must still check exact wallet/chain/asset/route/transaction bytes before key access and signing, and reconcile hashes, fees and finality afterward.

`python3 scripts/test-authorized-rpc.py` copies byte-identical production networking, scheduling, model constants and RobinHood base-operation source into an isolated narrow package. It resolves the shipping Starscream revision and the wallet's pinned Reachability revision, records source hashes, and requires 37 distinct passing XCTest cases with no skips. Tests exercise the real SDK and writer queue with controlled transport/clock fixtures; Starscream separately supplies real local TCP coverage. This does not replace a full iOS app build, migration tests, physical devices or distribution acceptance. No resolved production dependency is patched.

Request-ID allocation excludes pending, in-progress and active-subscription IDs. It uses a bounded search and fails before encoding when the usable ID space is exhausted.

The public manual-ID API reserves its identifier until successful subscription registration. Concurrent RPC preparation excludes these reservations. Registration is serialized and rejects zero or conflicting IDs without replacing an existing request/watcher. Existing wallet callers register synchronously. An abandoned reservation remains until engine destruction; exhaustion fails closed rather than recycling an identifier that a delayed caller still owns.
